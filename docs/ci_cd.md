## 📘 Управление релизами с помощью тегов

### 🔍 Текущее состояние

```bash
# Где я и что в рабочей директории
git branch --show-current          # ожидается main
git status                         # ожидается "working tree clean"

# Последние коммиты — видно, что в HEAD
git log --oneline -3
```

### 🏷️ Просмотр тегов

```bash
# Локальные теги
git tag

# Теги на GitHub
git ls-remote --tags origin
```

### 🗑️ Удаление тега (если нужно перевыпустить)

```bash
# Локально
git tag -d v0.0.1

# На GitHub
git push --delete origin v0.0.1

# Если релиз остался — удалить вручную: GitHub → Releases → Delete
```

> Удаление тега через `git push --delete` **не всегда** удаляет связанный релиз. Если релиз остался — почистите его вручную.

### 🚀 Ритуал нового релиза

#### Шаг 1. Подготовить изменения и запушить в `main`

```bash
git add .
git commit -m "feat: adaptive theme support"
git push origin main
```

Дождитесь, пока CI на `main` станет зелёным. Если бот `git-auto-commit-action` закоммитил `style: apply gofmt [skip ci]` — подтяните его:

```bash
git pull origin main
```

#### Шаг 2. Создать пустой коммит-маркер (важно!)

```bash
git commit --allow-empty -m "chore: release vX.Y.Z"
git push origin main
```

**Зачем это нужно.** GitHub Actions пропускает workflow, если в сообщении коммита, на который указывает тег, есть `[skip ci]`. Бот `gofmt` коммитит именно с `[skip ci]`, поэтому тег на ботский коммит **не запустит релиз**. Пустой коммит `chore: release vX.Y.Z` снимает эту проблему и явно маркирует точку релиза.

#### Шаг 3. Создать тег

```bash
git tag vX.Y.Z
```

#### Шаг 4. Проверить, на что указывает тег — **до пуша**

```bash
git show vX.Y.Z --no-patch --format="%H %s"
```

Ожидается: `<хеш> chore: release vX.Y.Z` — тот же хеш, что и `git rev-parse HEAD`, **без** `[skip ci]`.

#### Шаг 5. Запушить тег

```bash
git push origin vX.Y.Z
```

#### Шаг 6. Убедиться, что тег дошёл до GitHub

```bash
git ls-remote --tags origin | grep vX.Y.Z
```

В Actions должен появиться **отдельный запуск** для тега (не для `main`). В нём выполнятся `test` → `release` → `build-appimage` → `build-packages`.

### 📊 Семантическое версионирование

| Тип | Пример | Когда |
|-----|--------|-------|
| **PATCH** | `0.1.0 → 0.1.1` | Исправили баг, новой функциональности нет |
| **MINOR** | `0.1.1 → 0.2.0` | Добавили функцию (прогресс-бар, сохранение FQBN) |
| **MAJOR** | `0.2.0 → 1.0.0` | Сломали совместимость или вышли в стабильную версию |

### 🔄 Перевыпуск тега (если что-то пошло не так)

```bash
# Удалить локально и на GitHub
git tag -d vX.Y.Z
git push --delete origin vX.Y.Z

# Если релиз остался — удалить вручную на GitHub (Releases → Delete)

# Создать заново на актуальном main
git tag vX.Y.Z
git push origin vX.Y.Z
```

Если проблема была в `[skip ci]` — не забудьте сначала создать пустой коммит (Шаг 2 выше), иначе ситуация повторится.

---

### ⚠️ Частые ошибки

| Симптом | Причина | Решение |
|---------|---------|---------|
| Actions не запустился на тег | В коммите тега есть `[skip ci]` | Создать пустой коммит `chore: release vX.Y.Z` и пересоздать тег |
| В Actions только `test`, `release` серый | Запуск был на `main`, а не на теге. `release` имеет `if: startsWith(github.ref, 'refs/tags/v')` | Проверить, что запуск помечен тегом, а не веткой |
| Тег есть локально, нет на GitHub | Забыли `git push origin vX.Y.Z` | Запушить |
| Релиз есть, артефактов нет | `release` упал или был пропущен | Смотреть логи `test` и `release` в Actions |

## 📌 Что изменилось и почему

1. **Исправлен порядок**: проверка `git show vX.Y.Z` теперь стоит **после** `git tag` и **до** `git push` — именно там она имеет смысл.
2. **Убраны дубликаты `git show`** — команда встречается один раз, в правильном месте.
3. **Пустой коммит больше не «опциональный»** — это ключевой шаг, без которого релиз может не запуститься. Объяснено, почему.
4. **Добавлен шаг «проверить, что тег дошёл до GitHub»** (`git ls-remote`) — раньше его не было, а это частая причина «релиз не появился».
5. **Добавлена таблица частых ошибок** — с симптомами и решениями, чтобы не гадать по логам.
6. **Разделены «просмотр», «удаление», «создание»** — логические блоки вместо сплошного потока команд.
7. **Плейсхолдеры приведены к `vX.Y.Z`** — раньше `v0.1.2` использовался и как пример, и как плейсхолдер, что путало.
8. **Добавлено предупреждение про `[skip ci]`** — в исходнике этой критичной детали не было, а именно на ней вы и споткнулись.
